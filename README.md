# MusicVMAuto

用于 VMware Workstation 多虚拟机中的音乐客户端自动化。当前先做 **IP 验证 + QQ 音乐**，后续再接酷我音乐和 A-1 ~ A-50 批量切换。

## 当前架构

程序只运行在 VMware 外面的宿主机。虚拟机里不安装 Python、不复制源码、不额外驻留程序。

正式方案已经从“固定坐标”改为 **视觉识别**：每一步先截图找到当前按钮，再点击，因此 VMware 窗口移动后不依赖旧坐标。

## v0.4：IP 验证 + QQ 音乐视觉版

入口：

```bat
python host_visual.py
```

或运行 GitHub Actions / `build_host.bat` 生成的：

```text
MusicVMAutoVisual.exe
```

### 第一次只录模板

点“记录”后程序最小化，把鼠标慢慢移动到目标中央，准备好后按 **F8** 保存；按 **Esc** 取消，没有倒计时。

建议先录：

1. `线路设置`
2. `验证所有IP`
3. `验证成功 √`
4. `QQ音乐加载完成标志`
5. `第1个歌单`
6. `第2个歌单`
7. `歌单播放按钮`

`正在播放状态`、`QQ普通弹窗关闭按钮` 是可选模板。

模板保存在 EXE 同目录下的：

```text
templates\
```

正常情况下只需录一次；某一步以后识别失败，只重新录那一个模板即可。

## IP 验证逻辑

严格复用之前稳定版的规则：

```text
线路设置
→ 如果已有 √，直接成功
→ 否则只点击“验证所有IP”
→ 等待 √
→ 没有 √ 再点同一个按钮
→ 最多 3 次
→ 仍失败则停止并截图
```

不会点击：重新加载线路、删除IP、验证勾选IP等其他按钮。

视觉识别先在上一次成功位置附近快速找；找不到时扩大到整个 VMware 窗口搜索。识别分数低于安全阈值时不点击。

## QQ 音乐逻辑

虚拟机内默认启动路径：

```text
C:\Program Files (x86)\Tencent\QQMusic\QQMusic.exe
```

宿主机取得虚拟机输入焦点后使用：

```text
Win + R
→ 输入 QQMusic.exe 完整路径
→ Enter
```

因此不再依赖桌面 QQ 音乐图标的位置。

然后：

```text
等待 QQ 音乐加载完成
→ 处理已经录制的普通弹窗
→ 根据日期选择歌单1 / 歌单2
→ 识别并点击播放按钮
→ 如果录了“正在播放状态”模板，再做最终确认
```

当前基准日期：

```text
2026-08-12 = 歌单1
2026-08-13 = 歌单2
之后每天 1 / 2 交替
```

## 失败处理

任何关键目标识别失败都不会使用固定坐标乱点。失败时当前 VMware 画面会保存到：

```text
failures\
```

后续只需要针对失败步骤重新录模板。
